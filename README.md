## Сложность `StreakCalculator.daysInARow`

Если рассматривать в худшем случае, то сложность алгоритма будет O(n).
n - число всех записей.

Проход по каждой дате записи (`for (MoodEntry entry : entries)`) + Проверка, что `days` содержат `cursor`.

O(n) + O(n) = O(2n) = O(n) (отбрасываем константу)

Квадратичного риска нет, т.к. используем HashSet. Если бы использовали не его, а List, то тогда бы HashSet был бы лечением.

Ответ агента:
- **Время: O(n)**, где n — число записей. Один проход по списку: `toLocalDate()` и `HashSet.add` стоят O(1) амортизированно на запись. Затем цикл `while` делает не больше k ≤ n шагов (длина стрика), и каждый `contains` — O(1). Итого O(n + k) = O(n).
- **Память: O(n)** — в `HashSet` не больше n уникальных дат.
- **Квадратичный риск:** проверка вхождения даты внутри цикла. Если бы `days` был `ArrayList` (или искать по `entries` через `contains`/`anyMatch`), каждая проверка стоила бы O(n), и вся функция выродилась бы в O(n²).
- **Лечение:** `HashSet<LocalDate>` — membership-проверка за O(1) (уже используется). Компромиссный вариант — `TreeSet`, но там O(log n) на проверку.
